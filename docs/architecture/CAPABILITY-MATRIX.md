# Management client coverage

Ternuxx runs on Native Termux as the host and control plane, with optional managed Debian Trixie and Ubuntu Noble PRoot profiles. This table describes current source paths. Native `proot`/`proot-distro` and the Debian Trixie guest are installed on the observed device. P11 live acceptance passed on this device; it does not establish clean-device replay, broad device support, physical rotation behavior, or accessibility qualification.

All clients must route supported actions through the same typed service, authorization, and preview/confirmation contract. A source-level audit found and removed a redundant `native.ssh.status` alias: CLI, TUI, Web and GTK now use the canonical `ssh.inspect` route for SSH diagnostics. The shared service has 147 unique operation IDs, all classified in its resource or domain catalog. This resolves one duplicate contract; per-operation behavior and rendered-client acceptance remain open in the [audit evidence](../evidence/2026-10-24-client-dispatch-audit.md). Unsupported actions remain unavailable. The current runtime and phase state are recorded in [CURRENT_STATE.md](../../CURRENT_STATE.md), [current PRoot restoration evidence](../evidence/2026-10-24-p11-proot-source-restoration-audit.md), and [qualification guidance](../testing/README.md).
