# Management client coverage

Ternuxx runs on Native Termux as the host and control plane, with optional Debian PRoot workloads. This table describes current source paths. Native `proot`/`proot-distro` and the Debian Trixie guest are installed on the observed device. P11 live acceptance passed on this device; it does not establish clean-device replay, broad device support, physical rotation behavior, or accessibility qualification.

| Area | Current reach | Remaining work |
|---|---|---|
| Shared service | Typed Native and optional PRoot operations, an explicit tested authorization and Web-session security class for every operation, exact plans, terminal broker lifecycle, and recovery | Finish rendered/accessibility client review and clean-device replay |
| CLI | Native desktop, package, SSH, recovery, graphics, Cron, guided setup, bounded CPU/Vulkan/HTP AI routes, PRoot setup/status/profile/session inspection, receipt-verified replay-guest retirement/restore, exact-plan stop, shortcut add/remove/sync/rollback, reversible legacy Turnip ICD migration, exit-proven record reconciliation, plus `tx terminal` | Clean-device Debian setup replay and remaining release qualification |
| TUI | Shared Native workflows, Debian status/profile/session/app/probe, guided install launched from the attached TUI terminal, receipt-verified replay-guest retirement/restore with exact preview and typed confirmation, exact-preview stop, shortcut add/remove/sync/rollback, exit-evidence inspection/reconciliation that never signals, optional broker setup/start, interactive terminal handoff, and bounded CPU/Vulkan/HTP routes | Legacy ICD migration remains an attached Native CLI workflow; fresh-guest apply remains unverified on this device because the existing guest must be preserved; accessibility review and clean-device replay |
| Web | Authenticated loopback UI, Native management, Debian status/profile/session/probe/app, attached-CLI setup handoff, receipt-verified replay-guest retirement/restore with a dedicated `proot.replay.manage` session grant and exact preview, exact-preview stop, shortcut add/remove/sync/rollback, exit-evidence inspection/reconciliation, vendored xterm terminal, preview-confirmed broker setup/start, and bounded CPU/Vulkan/HTP routes | Fresh guest setup is available through direct Web preview/apply with a dedicated `proot.install.manage` scope; legacy ICD migration remains CLI-only; accessibility/narrow-screen review and clean-device replay |

| Software/AI | Curated htop/tmux/tree lifecycle and HOME-scoped tree listing across all clients; bounded CPU/Vulkan/HTP inference through the shared service in CLI/TUI/Web/GTK, with backend-specific status and offload checks | CPU/Vulkan sustained qualification, experimental Mesa/Freedreno provenance and clean install, plus HTP stability/model coverage remain open; see the [feature matrix](../testing/FEATURE-MATRIX.yaml) and [P12 evidence](../evidence/2026-10-24-native-acceleration-live-check.md).

All clients must route supported actions through the same typed service, authorization, and preview/confirmation contract. A source-level audit found and removed a redundant `native.ssh.status` alias: CLI, TUI, Web and GTK now use the canonical `ssh.inspect` route for SSH diagnostics. The shared service has 147 unique operation IDs, all classified in its resource or domain catalog. This resolves one duplicate contract; per-operation behavior and rendered-client acceptance remain open in the [audit evidence](../evidence/2026-10-24-client-dispatch-audit.md). Unsupported actions remain unavailable. The current runtime and phase state are recorded in [CURRENT_STATE.md](../../CURRENT_STATE.md), [current PRoot restoration evidence](../evidence/2026-10-24-p11-proot-source-restoration-audit.md), and [qualification guidance](../testing/README.md).
