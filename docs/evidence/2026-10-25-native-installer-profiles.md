# Native installer profile validation

**Date:** 2026-10-25 (Asia/Dhaka)  
**Evidence class:** repository tests and direct Native Termux package previews  
**Source commit before this implementation:** `ff3a52535bf80476425f70a2b5e8e8306fab1f0d`

The Native package installer now offers `minimal-native`, `full-native`, `graphical`, `developer`, `native-proot-provider`, and `custom` profiles. Custom selection accepts only the fixed `desktop`, `audio`, `proot`, `graphics`, and `developer` groups, always including the Native Python management core. Profile selection changes the requested package roots; dependency resolution, repository-origin validation, no-upgrade/no-removal policy, exact saved plan, and apply verification remain in the existing shared APT engine. Interactive mode is a TTY chooser that produces a preview; `--profile` is the non-interactive path.

On the live Native Termux host, `./tx install preview --profile developer --verbose` resolved 11 new packages (including CMake, GDB, Make, and dependencies) exclusively from the signed official `termux-main` index, with zero upgrades and zero removals. The preview was recorded; no package was applied. The resource estimate reported 22.4 MiB of archive data, 134.8 MiB installed payload, 96.2 GiB free on the Termux prefix filesystem, and 4.8 GiB available of 11.0 GiB host memory. Per-package figures came from the exact package/version APT metadata; this is a snapshot and approximate storage estimate, not an install result or memory guarantee. A live `./tx install interactive` run showed all six choices; selecting Minimal Native Workstation reported the Python core already installed and made no package changes.

`tests.test_package_plan` now passes 23 tests, including profile composition, custom allowlist rejection, a synthetic minimal-profile preview followed by exact-profile apply through the same transaction engine, and low-storage refusal before APT or an applying record. Three resource-estimator tests cover exact version/architecture selection, conflict/missing-data handling, and safe package-name validation; the installer integration also checks structured estimate output and a low-storage refusal before APT starts. The full local suite originally passed 1,099 tests in 115.512 seconds. After adding the estimator, capacity preflight, and failed-transaction journal it passed 1,104 tests in 123.594 seconds. A new integration test confirms insufficient estimated storage refuses apply before APT starts and before an `applying` record is written. The latest `env -u LD_LIBRARY_PATH bash scripts/repo_test.sh` passed 1,105 tests in 138.885 seconds; CLI help, document hash/link audit, strict README bridge, and `git diff --check` passed. GitHub Actions run [40179434997](https://github.com/soobujiah/ternuxx/actions/runs/40179434997) passed 1,103 tests in 46.449 seconds for the resource-estimate addition, with both validation and state-sync jobs successful. Controlled tests verify `applying`/`failed` records and fresh-preview recovery guidance, and verify a low-storage refusal before APT or an `applying` record; GitHub validation of these latest changes is pending. GitHub Actions run [40178757853](https://github.com/soobujiah/ternuxx/actions/runs/40178757853) passed for commit `f9ab7ca6613a4babc483466ea6c759bb3fe653f8`: 1,099 tests in 37.360 seconds, CLI help contract passed, and validation plus state-sync jobs succeeded.

The native-proot-provider profile installs `proot-distro` only; Debian guest creation remains a separate preview-confirmed operation. Failed APT attempts now record `applying`/`failed` transaction outcomes and recommend a fresh plan before retry; an interrupted process can leave an `applying` record without a terminal outcome. The requested combined Native-plus-fresh-guest preset, interactive progress/resume UI, and Bangla installer localization remain open.
