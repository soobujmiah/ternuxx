# Native installer profile validation

**Date:** 2026-10-25 (Asia/Dhaka)  
**Evidence class:** repository tests and direct Native Termux package previews  
**Source commit before this implementation:** `ff3a52535bf80476425f70a2b5e8e8306fab1f0d`

The Native package installer now offers `minimal-native`, `full-native`, `graphical`, `developer`, `native-proot-provider`, and `custom` profiles. Custom selection accepts only the fixed `desktop`, `audio`, `proot`, `graphics`, and `developer` groups, always including the Native Python management core. Profile selection changes the requested package roots; dependency resolution, repository-origin validation, no-upgrade/no-removal policy, exact saved plan, and apply verification remain in the existing shared APT engine. Interactive mode is a TTY chooser that produces a preview; `--profile` is the non-interactive path.

On the live Native Termux host, `./tx install preview --profile developer --verbose` resolved 11 new packages (including CMake, GDB, Make, and dependencies) exclusively from the signed official `termux-main` index, with zero upgrades and zero removals. The preview was recorded; no package was applied. The resource estimate reported 22.4 MiB of archive data, 134.8 MiB installed payload, 96.2 GiB free on the Termux prefix filesystem, and 4.8 GiB available of 11.0 GiB host memory. Per-package figures came from the exact package/version APT metadata; this is a snapshot and approximate storage estimate, not an install result or memory guarantee. A live `./tx install interactive` run showed all six choices; selecting Minimal Native Workstation reported the Python core already installed and made no package changes.

The `native-proot-provider` profile installs `proot-distro` only. The new `native-debian` preset first reviews exact Native APT and fresh Debian guest plans, then applies them in order through the existing installers; when Native packages are already installed, only the guest plan is required. The guest installer still uses hidden terminal password prompts. Failed APT attempts record `applying`/`failed` outcomes and recommend a fresh plan before retry; an interrupted process can leave an `applying` record without a terminal outcome. Interactive progress/resume UI and Bangla installer localization remain open. This source change is test-verified; the guest has not yet been created on the live device.
