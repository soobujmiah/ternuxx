# Debian desktop catalog extension — 2026-10-25

The Debian Trixie desktop catalog supports XFCE, LXQt, LXDE, MATE, GNOME, KDE Plasma, and Cinnamon. The Debian guest uses the pinned `debian:trixie-20261005` image and recorded setup profile `ternuxx-debian-trixie-workstation`. GNOME (`gnome-core` 1:48+2), Plasma (`kde-plasma-desktop` 5:162), and Cinnamon (`cinnamon-desktop-environment` 6.4.1) were installed through a Ternuxx preview-bound transaction. The exact additional transaction covered 805 packages, with no upgrades or removals; the verified guest now has 1,526 installed packages. An interrupted earlier apply was recovered with an exact failed-plan-bound dpkg recovery preview, and `dpkg --audit` is clean.

The package planner filters unselected desktop meta-packages and retains the shared manifest receipt. Standalone and nested launch routing map each catalog ID to a fixed command argv. Shortcut sync preview/apply generated launchers for all four installed Debian sessions (XFCE, GNOME, Plasma, Cinnamon) and 52 discoverable guest application entries, with no conflicts. Desktop launch choices are exposed through the CLI, TUI, Web and GTK management center. The Native registry also supports installed XFCE, LXQt, MATE, Cinnamon, and Plasma sessions, but only Native XFCE is installed on this device.

Live acceptance on 2026-10-25: Native XFCE on `:1` stayed running and was restored after the standalone test. Debian XFCE nested through Xephyr on `:2` launched `xfce4-session`, `xfce4-panel`, `xfdesktop`, and `xfwm4`; `xwininfo -root -tree` enumerated the desktop windows. Its GLES context reported `zink Vulkan 1.4 (Adreno (TM) 825 (MESA_TURNIP))`, which verifies a context/device string only, not rendered frames or accelerated application workloads.

GNOME nested launch reached Xephyr and emitted the same GLES context string, then `gnome-session` aborted because the PRoot guest has no system bus and `gnome-session-check-accelerated` could not find a supported GTK GLES configuration. Plasma started its session process but reported unavailable DRI3 and failed GLX initialization; its window tree did not show a verified usable panel/session. Cinnamon started its session manager and some session clients but reported an unsupported session type, lacked a verified Cinnamon window manager/panel, and depended on unavailable system services. These three sessions are installed and shortcut-routed, but their live desktop acceptance fails and they must not be described as working.

The standalone `:0` XFCE test passed process/window-tree acceptance: using the recorded Debian user, `xwininfo -root -tree` showed `xfce4-panel`, `xfdesktop`, and `xfwm4`; the owned PRoot GUI was then stopped and Native XFCE restored on `:1`. The standalone graphics verifier reported Zink/Turnip OpenGL ES and GLX renderers and enumerated Adreno 825 Vulkan devices (plus llvmpipe); it explicitly does not verify frame presentation or application offload. `gui_visible` remains `unknown` because no Android screenshot/visibility interface is available in this runtime.

GNOME on standalone `:0` also aborted because the PRoot guest has no system bus. Plasma on `:0` remained at the `ksplash` window without a verified shell/panel and logged Qt/GLX failures. Cinnamon on `:0` ran its session manager but did not produce a verified Cinnamon shell/window manager/panel. These outcomes agree with the failed nested attempts; none of the three is accepted as a working desktop.

Other PRoot distribution providers and distro-specific clean system profiles are not implemented. Native LXQt installation is available through the exact-preview custom `lxqt` component. The session-only package and then the full LXQt meta-package were both installed via reviewed plans; Native `:1` startup failed (lock-screen manager / Qt XCB startup errors), so XFCE was restored. The custom installer now exposes exact-preview `mate`, `cinnamon`, and `plasma` package components, but those Native sessions were not installed/live-tested. Native GNOME is not packaged in the Termux repository. Native X11 graphics remains `llvmpipe`; a context or device enumeration result is not proof of frame presentation or application acceleration. See [Native Freedreno runtime recheck](2026-10-25-native-freedreno-runtime-recheck.md).
