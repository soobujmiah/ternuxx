# Distro-named managed guest install flow

## Behavior

`tx install debian --user NAME` is a short entrypoint to the pinned Debian guest installer. In an attached terminal it previews the exact target, then asks before applying that same plan, so the user does not copy a plan ID into a second command. `tx install debian preview --user NAME` remains review-only, and JSON/noninteractive calls remain preview-only. The flow defaults to XFCE and uses Ternuxx-managed guest configuration with available graphics/audio handoff. Password mode prompts only on an attached terminal; guest-only passwordless sudo remains an explicit alternative. Existing root filesystems are never replaced. Known distro names without a setup profile return a clear unsupported message.

After a Native profile apply, the CLI offers optional managed Debian setup. The TUI launches the guided command after closing its curses screen, Web uses direct typed preview/apply behind an optional session capability, and GTK launches the guided command in an embedded Native VTE terminal. GTK uses checkbox multi-select and labels accepted display routes; GNOME/Cinnamon are marked unverified and Plasma as standalone-only. The old `native-debian` combined installer remains available for automation that intentionally plans Native and guest together.

## Validation

The full repository suite passed 1,193 tests in 158.197 seconds after the GTK checkbox picker change and supervisor test-timeout follow-up. CLI help contract, document inventory, repository knowledge verification, `git diff --check`, 23 GTK UI contract tests, and `clang -fsyntax-only -Wall -Wextra` passed. This does not prove the rebuilt GTK window was rendered or interacted with live. The isolated CI timing report is documented in the [supervisor test-timeout follow-up](2026-10-26-supervisor-test-timeout.md).
- On the attached Native Termux host, `tx install debian --user sobuj --sudo-mode passwordless` returned `Ternuxx fresh container already exists; only an exact failed-plan resume is allowed`. A following read-only `tx proot status --json` still reported the installed `debian` alias, no managed guest sessions, and no host PRoot processes. No rootfs was changed.
- A non-interactive password-mode apply attempt stopped before password input with a clear attached-terminal requirement. No password was supplied.

## Limits

Only Debian has a pinned Ternuxx setup profile. Ubuntu, Alpine, Arch Linux, Fedora, and Void commands are refused until their distro-specific setup, graphics/audio configuration, and launch routes are implemented and verified. This source milestone does not claim fresh-device installation, rendered GUI launch, or workload-level guest GPU acceleration.

## Follow-up: distro-aware guest launch routing

On 2026-10-26, source review found that the Ubuntu Noble pinned install profile existed, but the standalone PRoot desktop launcher still assumed Debian for package inventory, session routing, and guest account lookup. The launcher now resolves the selected alias to its Ternuxx profile, uses provider-specific desktop packages and routes, accepts only exact Ubuntu/replay receipts for noncanonical aliases, and stores the guest alias in the standalone session record so later graphics checks return to the same guest. Ubuntu XFCE is catalogued for both standalone `:0` and nested `:2`; other desktop selections remain limited to provider catalog entries with accepted route evidence.

The normal paths remain short: `tx install debian` or `tx install ubuntu` prompts for the guest account, prints the pinned target and asks once before applying the same plan. After Native workstation installation, the CLI offers either managed guest. TUI, Web, and GTK expose a distro choice that opens the same guided installer; explicit two-plan-ID Native-plus-guest installation remains an advanced automation path. Other distros are not advertised until Ternuxx has a pinned manifest and route implementation.

Focused verification passed 141 unit tests across PRoot diagnostics, receipt checks, desktop catalog/routing, launch commands, graphics management, session state, and package planning; 60 TUI tests passed, including Debian and Ubuntu installer-launch cases. Shell syntax, Python compilation, CLI help contract, and `git diff --check` passed. These checks do not establish an Ubuntu install or GPU acceleration on device. Ubuntu Noble still requires live install, standalone `:0`, nested `:2`, graphics workload, and audio endpoint qualification before it is described as device-supported.
